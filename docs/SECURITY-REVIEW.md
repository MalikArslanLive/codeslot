# Security review findings

Scope: source review and executable permission/nonce/import/recovery assertions. Not an independent penetration test and not proof arbitrary PHP is safe.

Implemented boundaries: combined manage_options/unfiltered_html/edit_plugins gate, multisite super-admin restriction, object capabilities for metadata, nonce-protected POST writes, no public source REST exposure, inactive imports with limits and prevalidation, bounded revision history and error messages, opt-in uninstall deletion. Raw code is output only on matching frontend HTML routes and escaped in editors. Normal PHP is query-ready and excluded from REST/AJAX/cron. Explicit bootstrap PHP runs at init across request types and rejects query conditions.


Known design risks: trusted administrators can execute arbitrary destructive PHP/JS; exception recovery covers only direct evaluation and fatal shutdown best effort, not later callbacks or side effects; page caches can retain output or leak condition-specific responses unless varied; metadata backups/exports contain executable code; imports are bounded but trusted code still requires review; snippet locks do not constrain another code administrator. Review administrator-authored code and keep recovery access.



Automated review: production ZIP checked using WordPress Plugin Check 2.2.0 on a clean WordPress installation. Final observed output: “Success: Checks complete. No errors found.” Explicit line-level annotations explain intentional privileged raw output and eval. These are reviewed design exceptions, not a promise that arbitrary code is harmless. Nonce checks are explicit at the admin mutation entrypoint as well as centralized permission verification. One-time uninstall uses metadata APIs and a prepared prefix query for plugin-owned observation options.


New boundaries: extra mutation routes require the same combined capabilities and nonce. Full restore prevalidates sections before writes, disables imported execution while preserving the current site-wide Safe Mode state; it is not a database transaction or full-site backup. Diagnostics omit paths/URLs by default and never dump credentials/source. Event logs are capped at 100 records without error-message/source bodies. Virtual routes have fixed filenames/MIME types, deny direct query-string access and defer to physical files; they cannot affect static server files or unregister existing workers. Pixel settings validate public IDs; script-context JSON is hex-escaped; enabled providers load their base tags automatically; the optional require_consent setting delays all provider loading until marketing consent. No customer contact details are sent by CodeSlot's WooCommerce event payloads. Vendor SDK behavior and browser delivery remain outside a local adapter test's guarantees.

Current upload review: both imports check the existing combined capabilities and nonce before accessing uploads. Files require a genuine PHP HTTP-upload origin, .json extension, successful upload status and no more than 5 MiB of actual bytes. Uploads are not persisted or executed. Schema validation and inactive restore behavior remain in place. Malformed nested provider events are filtered to strings and the provider allowlist; Snapchat IDs use a UUID-shaped pattern. Asynchronous cart context is read-only and scoped to the current WooCommerce session, with no order/customer contact data. Provider deduplication additionally includes the tracking ID.

Current import/restore review: exact duplicate detection never changes existing source/status/lock/history. A file-wide explicit Skip/Keep both/Replace choice handles same-name variants; only Replace overwrites one unlocked unambiguous entry, and prevalidation/rollback still protects failed imports. The full-editor nonce/capability gate authorizes clearing the one Lock checkbox; status/quick/bulk/Trash routes still reject locked entries. Restore preserves existing site-wide Safe Mode, including an existing emergency constant, and keeps all new entries disabled; explicit preserve-state applies only to replacements. Malformed mapping values are rejected before writes; missing/slug-less identities are skipped without inventing target IDs. HTML comment labels use generated scopes/IDs, exclude snippet names and strip unsafe label characters; no comments are added to PHP execution or non-HTML responses.

Source labels preserve plain-text and URL-like shortcode values exactly. Inline shortcode/manual markup uses compact comments so labels add no visible whitespace. Selector payloads keep their target DOM unchanged; the server-side selector configuration has boundary comments instead. Multiline source labels are used for global/individual hooks and block snippet locations.

Restore-choice review: all replacement/state/section policies are allowlisted before mutation. Full section plans, including enabled Pixel conversion-label requirements, are prevalidated. Skip/copy do not overwrite originals. Explicit snippet replacement requires a unique unlocked existing name and cannot target an uploaded ID. New entries remain disabled; preserve-state is an explicit opt-in for replacements. A later snippet insertion failure attempts to roll back prior replacements, history and taxonomy state. This does not claim a full database transaction across backup sections.

Condition-search review: only authenticated executable-code managers with a valid session nonce can query the endpoint. Search keys, input sizes and result counts are bounded; queries use WordPress APIs and returned content/terms require edit permissions. Titles are rendered with textContent, not HTML. Editor, import and restore consistently validate wrappers and provider IDs. Pixel head output keeps JSON hex encoding and existing order-key/customer/paid-state authorization; DOM-dependent cart bindings wait for readiness.

Dependency review: missing references fail closed for the complete snippet, including exclusions and negation. Required plugin identifiers are shape/size bounded and checked against WordPress’s valid active plugin paths; CodeSlot does not include or execute uploaded plugin paths. Requirements remain part of the guarded snippet configuration and restore validation. Availability is separate from the saved Active flag. Custom undeclared code dependencies cannot be inferred from arbitrary source.

Final validation review: malformed stored conditions and non-string locations pause execution with a readable reason. Positive taxonomy IDs are checked before querying, including on WordPress 6.5. Global/post/term writes and full restore share a 1 MiB UTF-8 byte limit per field; invalid submissions retain existing metadata. Full restore rejects empty section selections before any write and clearly says nothing was restored. Extra admin mutations use one explicit capability and nonce gate. Opt-in uninstall also removes stored temporary drafts/notices and single-site list preferences; multisite shared user preferences are retained because another site may still use them. External object-cache entries follow their configured expiry.

Malformed condition JSON or array-valued condition POST fields are rejected with a validation notice before saving; they cannot silently normalize to unrestricted execution. Explicit null condition/required-plugin values are rejected in the shared repository validator as well.
